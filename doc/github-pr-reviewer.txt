1. INTRODUCTION                                        *github-pr-reviewer-intro*

GitHub PR Reviewer is a powerful Neovim plugin for reviewing GitHub Pull
Requests directly in your editor. Review PRs with the full power of your
development environment - LSP, navigation, favorite files, and all your
familiar tools.

WHY THIS PLUGIN?~

Traditional PR review tools force you into a limited web interface. This
plugin brings PR reviews into your Neovim environment where you have:

• Full LSP support - Jump to definitions, find references, see type info
• Your favorite navigation tools - arrow.nvim, harpoon, telescope, etc.
• See the full codebase - Not limited to just the changed lines
• Efficient workflows - Built-in keybindings and smart change tracking
• Comprehensive comment management - Add, edit, delete, reply with great UX
• Pending comments - Draft comments in your GitHub pending review and submit
  them all together (from Neovim or GitHub)

Review faster, review better. Use the same environment where you write code
to review it.

2. REQUIREMENTS                                   *github-pr-reviewer-requirements*

• Neovim >= 0.11.0
• GitHub CLI (`gh`) installed and authenticated
• jj (Jujutsu) - the repository must be a jj repo; a colocated jj + git
  repo is needed for git tools (gitsigns, fugitive) to show the diff
• Optional: bat for syntax-highlighted previews in fzf-lua

4. QUICK START                                      *github-pr-reviewer-quickstart*

1. Run |:PRListReviewRequests| to see PRs requesting your review
2. Select a PR to review (Neovim |:cd|s into its review workspace, see
   |github-pr-reviewer-review-modes|)
3. Use |:PRReviewBuffer| to see all changed files
4. Navigate with LSP (gd, gr, K) and your favorite tools
5. Add pending comments with |:PRPendingComment|
6. Approve with |:PRApprove| or request changes with |:PRRequestChanges|
7. Clean up with |:PRReviewCleanup|

No need to commit or stash anything first: jj always snapshots your work
into its own change, which the review never touches.

5. COMMANDS                                          *github-pr-reviewer-commands*

MAIN MENU~
                                                     *:PR*
:PR                     Show interactive menu with all available actions.
                        Alias for |:PRReviewMenu|.

                                                     *:PRReviewMenu*
:PRReviewMenu           Show interactive menu with all available actions.
                        The menu adapts based on whether you're in review
                        mode or not.

REVIEW WORKFLOW~
                                                     *:PRReview*
:PRReview               Select and start reviewing a PR from the list of
                        open PRs. Fetches the PR with `jj git fetch` and
                        creates a review change on the merge-base with
                        the PR head's files restored into it (see
                        |github-pr-reviewer-review-modes|).

                                                     *:PRListReviewRequests*
:PRListReviewRequests   List PRs where you are requested as a reviewer.
                        Shows viewed status and allows marking PRs as
                        viewed without starting a review.

                                                     *:PRRefresh*
:PRRefresh              Re-fetch the PR and recreate the review change for
                        the new PR head (in the same workspace in
                        workspace mode), abandoning the old one. Local
                        edits made in the review change are discarded.
                        Comments and viewed files are re-fetched from
                        GitHub.

                                                     *:PRReviewCleanup*
:PRReviewCleanup        End the current review. In workspace mode, wipes
                        the workspace's buffers, |:cd|s back to where you
                        came from and runs `jj workspace remove pr-<N>`. In inplace
                        mode, returns to the change you were on. In both
                        modes, abandons the review change and clears the
                        session.

                                                     *:PRInfo*
:PRInfo                 Show PR information including stats, reviews,
                        merge status, and CI checks.

                                                     *:PROpen*
:PROpen                 Open the current PR in your web browser.
                        Only available in review mode.

                                                     *:PRReviewSessions*
:PRReviewSessions       List the open reviews of the repository (every
                        workspace whose working copy is a `pr-review #<N>`
                        change) and open, switch to, or remove one
                        (<C-d>). See |github-pr-reviewer-session|.

                                                     *:PRLoadLastSession*
:PRLoadLastSession      Restore the last PR review session after
                        restarting Neovim. Restores PR number, review
                        location, modified files, viewed status, and
                        pending comments. In workspace mode, |:cd|s into
                        the review workspace.

                                                     *:PRReviewBuffer*
:PRReviewBuffer         Toggle the review buffer (interactive file
                        browser). Shows all changed files with viewed
                        status, additions/deletions, and navigation keys.

COMMENTS~
                                                     *:PRReviewComment*
:PRReviewComment        Show comments at the cursor line in a popup
                        window. Comments also appear automatically on
                        CursorHold.

                                                     *:PRLineComment*
:PRLineComment          Add a review comment on the current line. The
                        comment is submitted immediately to GitHub.

                                                     *:PRPendingComment*
:PRPendingComment       Add a pending comment on the current line. The
                        comment goes to your pending review on GitHub
                        (shown there as "Pending") and is submitted with
                        |:PRSubmitPendingComments|, |:PRApprove|,
                        |:PRRequestChanges| or on GitHub.

                                                     *:PRSubmitPendingComments*
:PRSubmitPendingComments
                        Submit your pending review as a comment, without
                        approving or requesting changes ("Submit Review
                        (Comment)" in the menu). Like GitHub's "Submit
                        review > Comment".

                                                     *:PRListPendingComments*
:PRListPendingComments  List all pending comments and navigate to the
                        selected one. Shows file path, line number, and
                        comment preview.

                                                     *:PRListAllComments*
:PRListAllComments      List ALL comments (both pending and posted) with
                        file preview. Includes author, file path, line
                        number, and status. Telescope and fzf-lua show
                        file previews with syntax highlighting.

                                                     *:PRReply*
:PRReply                Reply to a comment on the current line. Cannot
                        reply to pending comments (must be submitted
                        first).

                                                     *:PREditComment*
:PREditComment          Edit your comment on the current line. Works for
                        both pending and posted comments. Shows the
                        conversation thread for context.

                                                     *:PRDeleteComment*
:PRDeleteComment        Delete your comment on the current line. For
                        pending comments, removes it from the pending
                        review. For posted comments, deletes from GitHub.

                                                     *:PRComment*
:PRComment              Add a general comment to the PR (not tied to a
                        specific line).

REVIEW ACTIONS~
                                                     *:PRApprove*
:PRApprove              Approve the PR with an optional comment. If you
                        have pending comments, they will be shown for
                        confirmation and submitted together with your
                        approval. Afterwards you are asked whether to exit
                        the review; yes runs |:PRReviewCleanup|.

                                                     *:PRRequestChanges*
:PRRequestChanges       Request changes on the PR with a required reason.
                        If you have pending comments, they will be shown
                        for confirmation and submitted together with your
                        review.

6. CONFIGURATION                                       *github-pr-reviewer-config*

Configure the plugin by calling the setup function: >lua

    require("github-pr-reviewer").setup({
      -- "workspace": review in a separate jj workspace (:cd into it)
      -- "inplace": review change in the current workspace
      review_mode = "workspace",

      -- fun(repo_root, pr_number) -> path for the review workspace
      workspace_path = nil,

      -- Picker: "native", "fzf-lua", or "telescope"
      picker = "native",

      -- Open modified files after starting review
      open_files_on_review = true,

      -- Show PR comments as virtual text in buffers
      show_comments = true,
      comment_indicator_position = "right_align", -- or "eol"

      -- Show icons/emojis in UI
      show_icons = true,

      -- Show floating windows with PR info, stats, and keymaps
      show_floats = true,

      -- Key to mark file as viewed and go to next file
      mark_as_viewed_key = "<CR>",

      -- Key to toggle floating windows visibility
      toggle_floats_key = "<C-r>",

      -- Remove the selected review in the |:PRReviewSessions| picker
      review_sessions_delete_key = "<C-d>",

      -- Commit-based reviewing
      commit_mode_toggle_key = "<C-t>",
      next_commit_key = "<C-n>",
      prev_commit_key = "<C-p>",

      -- Two-way sync of viewed files with GitHub's "Viewed" checkboxes
      sync_viewed_with_github = true,

      -- Key to go to next modified file
      next_file_key = "<C-l>",

      -- Key to go to previous modified file
      prev_file_key = "<C-h>",
    })
<

workspace_path          (function|nil, default: nil)
                        `function(repo_root, pr_number) -> path` for the

                        `~/.prr/<github-repo-name>-pr-<number>` (repo name

                                                     *github-pr-reviewer.picker*

                        Picker to use for PR selection and other lists.
                        Options: "native", "fzf-lua", "telescope"

show_comments           (boolean, default: true)

comment_indicator_position (string, default: "right_align")
                        Where the comment count of a commented line is
                        shown: "right_align" (right edge of the window) or
                        "eol" (right after the line's text).

show_icons              (boolean, default: true)

                        text-only interface.

show_floats             (boolean, default: true)
                        Show floating windows with PR info, stats, and
                        keymaps during review. Can be toggled on/off with
                        |github-pr-reviewer.toggle_floats_key|.

                                                     *github-pr-reviewer.mark_as_viewed_key*
mark_as_viewed_key      (string, default: "<CR>")

                                                     *github-pr-reviewer.toggle_floats_key*
toggle_floats_key       (string, default: "<C-r>")

                        works in review mode.

review_sessions_delete_key (string, default: "<C-d>")

next_file_key           (string, default: "<C-l>")

7. WORKFLOWS                                       *github-pr-reviewer-workflows*

BASIC REVIEW WORKFLOW~

1. Start a review: >vim
    :PRListReviewRequests
<
2. Select a PR from the list

3. Open review buffer to see all files: >vim
    :PRReviewBuffer
<
4. Navigate with LSP:
   • gd - Go to definition
   • gr - Find references
   • K - Hover documentation

5. Add pending comments as you review: >vim
    :PRPendingComment
<
6. Mark file as viewed: Press <CR> (default)

7. Approve or request changes: >vim
    :PRApprove
    " or
    :PRRequestChanges
<
8. Clean up: >vim
    :PRReviewCleanup
<

REVIEW MODES~
                                                     *github-pr-reviewer-review-modes*

Starting a review runs `jj git fetch` (only the base branch from origin and
the head branch from origin or the fork remote) and creates a review
change, whose description starts with `pr-review #<N>`. The review change
sits on the merge-base with the PR head's files restored into it: files on
disk are exactly the PR head, while git's HEAD (colocated repo) is the diff
base, so git tools show the PR's changes (see |github-pr-reviewer-diffs|).
The PR's commits are never the working copy, so local edits can't rewrite
them; they go into the throwaway review change.

Workspace mode (default, `review_mode = "workspace"`): >bash
    jj workspace add --name pr-<N> -r <merge-base> \
      -m "pr-review #<N>: <head> -> <base>" <path>
    jj restore --from <pr head>   # in the new workspace
<
Neovim |:cd|s into the workspace (and back to where it came from when the
review is cleaned up or put aside). Your original checkout is untouched (no
LSP/watcher churn). An existing
`pr-<N>` workspace is reused (refresh, or a review never cleaned up).
Files jj doesn't track (node_modules, .env, virtualenvs) are not present
in the new workspace, so LSP/builds may not work there; use inplace mode
if you need them.

If you start a new review choosing "continue without cleanup", the old
workspace stays on disk. Remove it with `jj workspace remove pr-<N>`.

Inplace mode (`review_mode = "inplace"`): runs
`jj new <merge-base> -m "pr-review #<N>: ..."` and
`jj restore --from <pr head>` in the current workspace and remembers the
change you were on. Cleanup goes back to it with `jj edit` (or `jj new` on
its parents if jj auto-abandoned it because it was empty).
Your work in progress lives in its own change, so it is never touched.

Diffs are computed against the merge-base of the PR head and the base
branch (`heads(::head & ::base@origin)`), the same base GitHub's "Files
changed" uses, so base-only changes don't show up. Renames are shown as a
delete + an add.

FROM THE SHELL~
                                                     *github-pr-reviewer-cli*
`bin/prr` (needs `gh`, `jj` and `fzf`) picks a PR (review requested by
default, CTRL-T toggles all open PRs, `--all` starts there, `prr <N>`
skips the picker), `cd`s into its review workspace and starts Neovim
reviewing it. A missing workspace is created first by a headless Neovim.
Inside a jj repo it lists that repo's PRs; anywhere else the PRs of every
jj repo up to two levels under `$PRR_REPO_DIRS` (default `~/proda:~`).

`prr clean` removes the review workspaces of the current repo (workspace,
directory, review change, session); `prr clean --all` those of every repo
with a workspace in `~/.prr`, plus leftover directories there.

`require("github-pr-reviewer").prepare_pr(N)`    *github-pr-reviewer.prepare_pr()*
    Headless helper: create the review workspace of PR N (and save its
    session), print its root and quit. Prints the repo root in inplace mode.

`require("github-pr-reviewer").open_pr(N)`          *github-pr-reviewer.open_pr()*
    Open the review of PR N: its existing review if any, else start one.

`require("github-pr-reviewer").cleanup_reviews()`  *github-pr-reviewer.cleanup_reviews()*
    Headless helper: remove every review workspace of the repository
    (workspace and directory, review change, session) and quit.

PENDING COMMENTS WORKFLOW~
                                                     *github-pr-reviewer-pending-comments*

The most efficient way to review is using pending comments:

1. As you review, add pending comments with |:PRPendingComment|
2. These go to your pending review on GitHub: only you see them, as
   "Pending", and you can continue (or submit) the review on GitHub
3. Continue reviewing, adding more pending comments
4. Use |:PRListPendingComments| to review all your draft comments
5. When ready, run |:PRApprove| or |:PRRequestChanges|
6. The plugin shows a preview of ALL pending comments
7. Confirm to submit your review + all pending comments at once

Benefits:
• Draft your thoughts as you review without interrupting your flow
• Review all your comments before submitting
• Submit everything together as a cohesive review
• Edit or delete pending comments before submission

NAVIGATION~
                                                     *github-pr-reviewer-navigation*

For hunks within a file, use your git tools (see |github-pr-reviewer-diffs|).

File Navigation (between modified files):
• <C-l> (default) - Go to next modified file
• <C-h> (default) - Go to previous modified file
• <CR> (default) - Mark file as viewed and jump to next file

View Controls:
• <C-r> (default) - Toggle floating windows visibility

All keybindings are configurable and only activate during PR review mode.

COMMIT-BASED REVIEWING~
                                                     *github-pr-reviewer-commit-mode*
Review the PR one commit at a time instead of all at once:

• <C-t> (default) - Toggle between the whole PR and single commits (the
  sidebar follows: file list for the whole PR, commit tree in commit mode)
• <C-n> / <C-p> (default) - Next / previous commit

In commit mode the review change is recreated on the commit's parents with
the commit's files restored into it (`jj new <parents>` + `jj restore --from
<commit>`), so the files on disk are the commit's version and git tools show
only that commit's changes. Going back to the whole PR does the same with the
merge-base and the PR head. Merge commits are listed against their
auto-merged parents, so the file list only shows conflict resolutions, while
git's HEAD is the first parent, so git tools show the merge against its first
parent. File list, file navigation and floats show the current commit.

In commit mode the sidebar lists the PR's commits (oldest first) by jj change
id (unique prefix highlighted like `jj log`: `PRReviewChangeIdPrefix`,
`PRReviewChangeIdRest`) with viewed progress; the current commit is expanded
to its files. <CR> on a commit enters it (on
the current one: fold/unfold), <CR> on a file enters its commit and opens it,
`m` toggles viewed for a file or a whole commit.

Viewed state is per commit: marking a file viewed in commit mode only covers
that commit's changes to it, and the file counts as viewed for the whole PR
once it is viewed in every commit that changes it. Marking a file viewed in PR
mode marks it in all of its commits. Viewed state is stored per commit SHA, so
after a force-push the rewritten commits start unviewed.

Viewed state is synced with GitHub (|github-pr-reviewer.sync_viewed_with_github|).
GitHub's "Viewed" checkbox is per file for the whole PR, so it follows the
PR-level state: a file is marked viewed on GitHub once it is viewed in every
commit that changes it, and unmarked as soon as it isn't. When a review starts,
is restored or refreshed (|:PRRefresh|), the GitHub state wins: files viewed
there are viewed in all their commits, files not viewed there (unmarked, or
changed since they were viewed) are unmarked in all of them.

Comments in commit mode: only comments made on that commit are shown, at their
line in that commit. New single comments are attached to that commit; pending
comments are only available in PR mode, because a GitHub review is submitted
against a single commit.

Unsaved edits in review buffers are discarded when switching commits.

REVIEW BUFFER~
                                                     *github-pr-reviewer-review-buffer*

The review buffer is an interactive file browser showing all changed files:

• Foldable directories: Press <CR> on a directory to collapse/expand it
  - ▼ = Expanded directory (showing files)
  - ▶ = Collapsed directory (files hidden)
• ✓ = File has been marked as viewed
• ○ = File not yet viewed
• Shows additions/deletions for each file
• Press <CR> on a file to open it (s / v: split / vertical split);
  double click works too
• Press m to mark a file viewed
• Fold directories (commits in commit mode) with |zo| / |zc| / |za| (the row
  under the cursor, or the one a file belongs to) and |zR| / |zM| (all)
• Press q to close
• Automatically refreshes as you mark files viewed
• The entry under the cursor gets a selection background
  (`PRReviewSelection`, linked to `CursorLine`); the open file / reviewed
  commit is bold (`PRReviewCurrent`). Override them with |nvim_set_hl()|.

CHANGE PROGRESS INDICATOR~
                                                     *github-pr-reviewer-progress-indicator*

When reviewing a file of the PR, three floating windows provide context:

General Float:
• File position - File x/total (plus Commit i/n in commit mode)

Buffer Float:
• Viewed status - Shows if the file has been marked as viewed
• Stats - +additions ~modifications -deletions
• Comments - 💬 Number of PR comments in this file

Keymaps Float:
• Shows available keyboard shortcuts for review mode

Toggle Floating Windows:
• Press <C-r> (default) to hide/show all three floating windows
• Set show_floats = false in config to disable them by default
• Useful when you want a cleaner view or need more screen space

VIEWING DIFFS~
                                                     *github-pr-reviewer-diffs*

The plugin doesn't draw diffs itself. Because git's HEAD in the review
checkout is the diff base, your git tools show exactly the PR's changes (or
the current commit's in commit mode):

• gitsigns.nvim - signs, ]c / [c hunk navigation, `:Gitsigns preview_hunk`
• vim-fugitive - `:Gvdiffsplit` for a side-by-side diff
• `git diff HEAD` in a terminal

This requires a colocated jj + git repo (workspace mode creates a git
worktree for the review workspace when the repo is colocated). Deleted files
can't be shown by git tools from the file list, so the plugin opens them as
a read-only `<path> [DELETED]` buffer with the base content.

SESSION PERSISTENCE~
                                                     *github-pr-reviewer-session*

The plugin automatically saves your review session state:

• Auto-save: Session is saved when you start a review
• Per PR: Each PR has its own session, keyed by the shared jj repo store
  (`<root>/.jj/repo`) and the PR number, so sessions are found from any
  workspace of the repo
• What's saved: PR number, review mode, review root, main root,
  workspace name, merge base, review change, previous change, modified
  files, viewed status, and pending comments
• Auto-cleanup: Session file is deleted when you run |:PRReviewCleanup|

Restore a session after restarting Neovim: >vim
    :PRLoadLastSession
<
If the current directory is a review workspace (its working copy is a
`pr-review #<N>` change), PR N is resumed, even if another PR's session is
newer; with no saved session for PR N, its review is started again in that
workspace. Anywhere else, the most recently saved session is restored.

|:PRReviewSessions| (`l` in the menu, `w` during a review) lists all open
reviews, found with `jj workspace list`, the current workspace's first, each
marked with whether a saved session exists. Picking one restores it (or
starts its review again). A loaded review of another PR is put aside first:
its session is saved and Neovim |:cd|s out, its workspace stays. <C-d>
(`review_sessions_delete_key`) removes the selected review: its workspace
(or inplace review change) and its session.

In workspace mode this |:cd|s into the review workspace.

Session files are stored in:
    ~/.local/share/nvim/github-pr-reviewer-sessions/

8. KEYMAPS                                           *github-pr-reviewer-keymaps*

RECOMMENDED KEYMAPS~

Add these to your config for quick access: >lua

    -- Quick menu access
    vim.keymap.set("n", "<leader>p", ":PR<CR>",
      { desc = "PR Review Menu" })

    -- Review workflow
    vim.keymap.set("n", "<leader>pr", ":PRReview<CR>",
      { desc = "Start PR review" })
    vim.keymap.set("n", "<leader>pl", ":PRListReviewRequests<CR>",
      { desc = "List review requests" })
    vim.keymap.set("n", "<leader>pc", ":PRReviewCleanup<CR>",
      { desc = "Cleanup PR review" })
    vim.keymap.set("n", "<leader>pi", ":PRInfo<CR>",
      { desc = "Show PR info" })
    vim.keymap.set("n", "<leader>po", ":PROpen<CR>",
      { desc = "Open PR in browser" })
    vim.keymap.set("n", "<leader>pb", ":PRReviewBuffer<CR>",
      { desc = "Toggle review buffer" })

    -- Comments
    vim.keymap.set("n", "<leader>pC", ":PRLineComment<CR>",
      { desc = "Add line comment" })
    vim.keymap.set("n", "<leader>pP", ":PRPendingComment<CR>",
      { desc = "Add pending comment" })
    vim.keymap.set("n", "<leader>pv", ":PRListAllComments<CR>",
      { desc = "List all comments" })

9. INTEGRATION                                   *github-pr-reviewer-integration*

ARROW.NVIM / HARPOON~
                                                     *github-pr-reviewer-arrow*
                                                     *github-pr-reviewer-harpoon*

Mark files you want to return to during review: >lua

    -- With arrow.nvim
    require("arrow").setup()

    -- With harpoon
    require("harpoon").setup()
<

Both plugins work seamlessly during PR review, letting you mark important
files and jump between them quickly.

LSP~
                                                     *github-pr-reviewer-lsp*

Your LSP is fully functional during PR review:
• gd - Go to definition
• gr - Find references
• K - Hover documentation
• <leader>rn - Rename
• All your LSP keybindings work normally

This is a huge advantage over web-based PR review - you can explore the
full codebase with full language intelligence.

TELESCOPE / FZF-LUA~
                                                     *github-pr-reviewer-telescope*
                                                     *github-pr-reviewer-fzf-lua*

Set your preferred picker in the config: >lua

    require("github-pr-reviewer").setup({
      picker = "telescope",  -- or "fzf-lua" or "native"
    })
<

Telescope and fzf-lua provide enhanced comment browsing with file previews:
• Telescope: Full file preview with syntax highlighting and highlighted
  comment line
• fzf-lua: File preview with bat/cat showing context around the comment

GITSIGNS.NVIM~
                                                     *github-pr-reviewer-gitsigns*

gitsigns.nvim is the recommended way to see the PR's hunks (the plugin has
no built-in diff view). In a colocated jj + git repo, git's HEAD in the
review checkout is the diff base and the git index matches it, so with a
default setup gitsigns shows exactly the PR's changes (or the current
commit's in commit mode): >lua

    require("gitsigns").setup({
      -- your gitsigns config
    })

    local gs = require("gitsigns")
    vim.keymap.set("n", "]c", function() gs.nav_hunk("next") end)
    vim.keymap.set("n", "[c", function() gs.nav_hunk("prev") end)
    vim.keymap.set("n", "<leader>hp", gs.preview_hunk)
<
With vim-fugitive, `:Gvdiffsplit` shows the current file side by side with
the diff base. See |github-pr-reviewer-diffs|.

10. TROUBLESHOOTING                          *github-pr-reviewer-troubleshooting*

NOT ON A REVIEW CHANGE~

You can only run |:PRReviewCleanup| while in a review, i.e. when the
current change's description starts with `pr-review #<N>`.

COMMENTS NOT SHOWING~

1. Make sure `show_comments = true` in your config
2. Check that you're authenticated: >bash
    gh auth status
<
3. Try |:PRReviewComment| to manually show comments at cursor

PR ACTIONS FAILING~

Ensure GitHub CLI is properly authenticated: >bash

    gh auth status
    gh auth login  # if not authenticated
<

FETCH FAILED~

If `jj git fetch` fails, you might have old fork remotes that are no
longer accessible. Clean them up: >bash

    jj git remote list
    jj git remote remove fork-<owner>
<

LEFTOVER REVIEW WORKSPACES~

A review that was never cleaned up leaves its workspace on disk: >bash

    jj workspace list
    jj workspace remove pr-<N>
<

PREVIEW NOT WORKING IN FZF-LUA~

Install bat for syntax-highlighted previews: >bash

    # macOS
    brew install bat

    # Ubuntu/Debian
    apt install bat

    # Arch
    pacman -S bat
<

If `bat` is not available, the plugin falls back to `cat`.
